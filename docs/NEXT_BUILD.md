# 다음 스토어 빌드 (0.3.0) 때 넣을 것

OTA로는 못 넣고 새 빌드가 있어야 하는 것들을 여기에 모은다. (2026-11-17 정리)

네이티브 코드가 들어가는 변경은 **빌드를 낼 때까지 main에 합치지 않는다.** main에서 내보내는 OTA는 0.2.0 빌드로 가는데,
새 네이티브 모듈을 쓰는 화면 코드가 섞이면 옛 빌드에서 앱이 죽는다. 빌드 직전에 버전을 0.3.0으로 올리고 합친다.

### 위젯에서 정한 것

- '오늘 뭐 하지' 위젯은 위젯 안에서 눌러 다시 뽑는 방식이라 iOS 17 이상에서만 된다.
  그보다 낮은 iOS에서는 위젯 고르는 목록에 **아예 나오지 않게** 한다 (위젯 선언에 `@available(iOS 17.0, *)`).
  나머지 세 위젯은 버전과 상관없이 보인다.
- '다음에 할 것' 위젯의 줄을 누르면 앱의 그 항목 화면으로 간다 (`doit2://item/<id>`).

## 넣기로 한 것에 더한 것

- 스토어 별점 요청: 기록이 세 번째가 되는 순간 한 번 (`lib/storeReview.ts`)
- 새 기능 사용 기록: 공유로 담기, 위젯으로 열기, 꾹 누르기 바로가기, 아이콘 바꾸기, 캘린더에 넣기, 초대 링크로 열기 (`app_steps`)
- 라이브러리를 Expo가 권하는 버전으로 맞춤 (2026-11-17)

## 빌드할 때 알아 둘 것

- 아이폰은 앱 말고 **확장이 두 개** 더 생긴다: `ShareExtension`(공유로 담기), `ExpoWidgetsTarget`(위젯).
  EAS 첫 빌드 때 확장마다 인증서·프로파일을 만들지 물어보니 만들라고 답한다.
  앱 그룹(`group.com.doit2.app`)과 연결 도메인(`applinks:doit2app.github.io`) 권한도 이때 등록된다.
- `npx expo prebuild --no-install`은 아이폰·안드로이드 모두 오류 없이 끝나는 것까지 확인했다 (2026-11-17).
  실제 컴파일(Xcode·Gradle)은 확인하지 못했다.
- **빌드가 깨질 때 떼어 내는 순서** (기능 하나가 나머지를 막지 않게):
  1. 위젯: `app.json`에서 `expo-widgets`와 `./plugins/withWidgetAutoRefresh` 플러그인 항목을, `app/_layout.tsx`에서 `<WidgetSync />` 줄을 뺀다.
     안드로이드 위젯만 문제면 `expo-widgets` 설정의 `enableAndroid`를 `false`로 바꾼다.
  2. 꾹 누르기 메뉴·아이콘 고르기(`expo-quick-actions`, 공식 모듈이 아님): 플러그인 두 항목과 `<QuickActionsSync />`를 빼면
     설정의 '앱 아이콘' 줄도 저절로 사라진다.
  3. 공유로 담기: `expo-share-intent` 플러그인 항목과 `<ShareInSync />`, `app/+native-intent.tsx`의 공유 줄을 뺀다.

## 같이 정리할 것

- '하트 두 개' 캐릭터 아이콘: 원본은 `assets/icon-drafts/`에 있다. 기본 아이콘은 지금 글자 아이콘으로 두고, 고르기 목록에 캐릭터로 넣었다.
- iOS 최소 버전: 2026-11-17에 `0.2.0`으로 올렸다 (지금 스토어 버전). 0.3.0이 스토어에 올라가면 아래 '업데이트 강제' 순서로 다시 올린다.
- 개인정보처리방침: Sentry 줄을 넣고 시행일을 2026-11-17로 바꿔 소개 사이트에 올렸다. 앱 안의 방침 변경 안내도 같은 날짜로 바꿨다.
  빌드가 며칠 늦어져도 방침이 먼저 올라가 있는 것은 문제없다.
- **스토어의 개인정보 신고 고치기** (직접): Sentry 때문에 수집하는 데이터가 늘었다.
  App Store Connect '앱이 수집하는 개인정보'에 진단 데이터(충돌·오류 기록)와 식별자(계정 id),
  Play Console '데이터 보안'에 앱 진단 정보(비정상 종료 로그)를 더한다.
- Sentry 소스맵: 0.3.1부터 올린다 (아래 '다음 빌드 (0.3.1)' 참고).
- **업데이트 강제**: 버전을 올리면 모두 새 버전으로 올리게 한다. 서버 `app_versions` 표의 `min_version`을 새 버전으로 바꾸면
  그보다 낮은 앱은 켤 때 업데이트 화면이 뜨고 스토어로 보낸다. **반드시 그 스토어에서 새 버전을 내려받을 수 있게 된 뒤에** 바꾼다
  (먼저 바꾸면 업데이트 화면에 갇힌다). 폰 종류마다 줄이 따로라서 심사가 끝난 쪽부터 바꾼다.

  ```sql
  update public.app_versions set min_version = '0.3.0', updated_at = now() where platform = 'android';
  update public.app_versions set min_version = '0.3.0', updated_at = now() where platform = 'ios';
  ```

- `patches/expo-widgets+58.0.29.patch`: `npm install` 뒤에 저절로 적용된다(`postinstall`). expo-widgets 버전을 올리면
  패치 파일 이름의 버전도 맞춰 다시 만들어야 한다 (`npx patch-package expo-widgets`).
- 빌드 뒤: 0.3.0용 OTA를 한 번 내보낸다 (버전이 바뀌면 OTA는 새 빌드로만 간다).

## 다음 빌드 (0.3.1) 때 넣을 것

- 안드로이드 앱 아이콘이 바꿀 때마다 하나씩 늘어나는 것 고치기: `patches/expo-quick-actions+6.0.2.patch`.
  라이브러리가 지금 켜진 아이콘을 메모리로만 알아서, 앱을 다시 켠 뒤 바꾸면 옛 아이콘을 끄지 않았다.
  고른 것만 켜고 등록된 나머지는 모두 끄게 했다. 이미 늘어난 사람도 아이콘을 한 번 더 바꾸면 하나만 남는다.
  패치는 네이티브 코드라 0.3.0 빌드에는 OTA로 안 간다 (main에 있어도 0.3.0 앱에는 영향 없음).
- Sentry 소스맵 올리기: 오류 위치가 줄여진 코드 대신 원래 파일·줄로 보이게 한다.
  - 스토어 빌드: 조직·프로젝트 이름(`youngjoolee` / `doit2`)은 `app.json`의 Sentry 플러그인에 있고, EAS 환경 변수 `SENTRY_AUTH_TOKEN`이 있으면 빌드 중에 저절로 올린다 (`app.config.js`). 토큰이 없으면 올리기를 꺼서 빌드는 그대로 된다.
  - OTA: `npm run update`가 플랫폼마다 `eas update` 뒤에 `npm run sourcemaps`로 `dist`의 소스맵을 올린다. 못 올려도 OTA는 그대로 나간다.
  - 번들에 디버그 ID를 넣으려고 `metro.config.js`를 `getSentryExpoConfig`로 바꿨다 (이건 OTA에도 바로 들어간다).
  - 토큰: Sentry의 Settings → Organization Tokens에서 만든 조직 토큰을 EAS production 환경에 `SENTRY_AUTH_TOKEN`(sensitive)으로 넣었다 (2026-11-24).
    바꿀 때는 아래를 실행하고 값을 물으면 새 토큰만 붙여 넣는다. `secret`으로 넣으면 이 PC에서 OTA 뒤에 올릴 때 읽지 못한다.

    ```powershell
    npx.cmd eas-cli env:create --name SENTRY_AUTH_TOKEN --environment production --visibility sensitive --force
    ```

    EAS에 `SENTRY_ORG`, `SENTRY_PROJECT`를 넣으면 `app.json` 값보다 먼저 쓰인다. 넣는다면 이름만 넣는다 (토큰을 넣지 않는다).

- 관리자 모드를 Face ID·지문으로 열기 (`expo-local-authentication`, `expo-secure-store`, `lib/adminBiometric.ts`).
  PIN으로 한 번 연 뒤 켜면, PIN을 이 폰의 보안 저장소에 생체 인증을 걸어 넣어 두고 다음부터 생체 인증으로 꺼내 서버에 보낸다.
  서버의 PIN 확인·틀린 횟수·잠금은 그대로다. 저장한 계정과 다른 계정이면 쓰지 않는다. 관리자 화면 아래에서 끄고 켠다.
  생체 인증 모듈은 나중에 앱 잠금을 넣을 때도 OTA로 쓸 수 있게 미리 넣는 의미도 있다.
- 옛 버전에서 늘어난 앱 아이콘 안내 (안드로이드): 아이콘 패치에 켜진 아이콘 수를 세는 `enabledIconCount`를 더했다.
  2개 이상이면 앱을 켤 때 한 번 알리고(`IconCleanupNotice`), 아이콘 화면에서는 지금 아이콘 그대로 '이 아이콘 하나만 남기기'를 누를 수 있다.
- 위 두 가지의 화면 코드는 0.3.0 빌드에 OTA로 가도 모듈·함수가 없어서 아무것도 보이지 않는다.
- 사진을 공유해서 담기: 공유 확장이 사진도 받는다 (아이폰 3장, 안드로이드 한 장·여러 장). 담기 화면의 사진 칸에 줄여서 넣는다 (`saveSharedPhoto`).
  0.3.0 빌드는 사진을 받지 않으니 이 화면 코드가 가도 달라지는 게 없다.
- 미리 넣어 둔 모듈 (기능은 나중에 OTA로): `expo-background-task`·`expo-task-manager`(위젯·알림을 백그라운드에서 새로 고치기), `lottie-react-native`(축하 애니메이션).
  지금은 쓰는 코드가 없다. 백그라운드 작업은 `TaskManager.defineTask`를 화면 밖(파일 맨 위)에서 불러야 한다.
- 안드로이드 앱 크기 줄이기: `expo-build-properties`로 R8(코드 줄이기)과 리소스 줄이기를 켰다.
  그래서 네이티브 오류 위치를 읽으려면 대응표(ProGuard mapping)가 필요해서, Sentry 토큰이 있을 때 Sentry 안드로이드 Gradle 플러그인이 같이 올린다 (`app.config.js`).
  **가장 깨지기 쉬운 부분이다.** 앱이 켜자마자 꺼지거나 어떤 화면에서만 죽으면 이 둘(`enableMinifyInReleaseBuilds`, `enableShrinkResourcesInReleaseBuilds`)을 먼저 끈다.

### 0.3.1 빌드 전후 점검 (2026-11-24)

- 빌드 전: App Store Connect API 키(`28L5QSV5H7`)가 지난번에 401이었으니 새 키로 바꿔 둔다.
- 심사 전: 새 기능 스크린샷(위젯, 공유로 담기)을 넣는다.
- 새 빌드에서 직접 눌러 볼 것: 갤러리·카톡에서 사진 공유 → 담기(한 장, 여러 장), 화면 전부 한 번씩 열기(R8 때문에), 관리자 모드 Face ID·지문(켜기 → 잠그기 → 생체 인증으로 열기 → 끄기), 아이콘 여러 개 안내(0.3.0에서 아이콘을 두 번 바꿔 늘려 둔 폰에 0.3.1을 덮어 설치).
- 그리고 0.3.0 이후 사용 기록이 공유로 담기·꾹 누르기 메뉴·캘린더 넣기는 0건, 위젯으로 열기는 1건이었다.
  고장인지 안 쓰는 건지 모르니 한 번씩 확인한다.
- 초대 링크 바로 열기(App Links/Universal Links): 링크로 연 기록이 웹 페이지를 거친 것(`web`) 1건뿐이다.
  안드로이드는 `assetlinks.json`의 지문 중 하나가 Play Console '앱 서명 키'의 SHA-256과 같은지 본다.
- 빌드가 스토어에 올라간 뒤: **안드로이드만** `min_version`을 `0.3.1`로 올린다 (아이콘 중복은 안드로이드에만 있다).
  이미 아이콘이 늘어난 사람은 아이콘을 한 번 더 바꾸면 하나만 남는다.

## 0.3.0을 낸 기록 (2026-11-17)

- 빌드: 아이폰·안드로이드 모두 0.3.0 (빌드 번호 5), 첫 시도에 성공. 둘 다 심사에 넣었다.
- 아이폰 인증서: 앱 그룹이 새로 켜져서 앱의 옛 프로파일이 무효가 됐다. 빌드 때 Apple 로그인을 하고
  앱·`ShareExtension`·`ExpoWidgetsTarget` 셋 다 **배포 인증서는 다시 쓰고, 프로파일은 새로** 만들었다.
- EAS에 저장된 App Store Connect API 키(`28L5QSV5H7`)가 빌드 때 Apple에서 401로 거부됐다. 그래서 빌드는
  Apple 로그인으로 했다. 제출은 같은 키로 됐지만, 다음에도 401이 나면 App Store Connect에서 키를 새로 만들어 바꾼다.
- 안드로이드 제출: `eas.json`의 `submit.production.android`에 따라 **프로덕션 트랙 초안**으로 올라간다.
  Play Console에서 출시 노트를 넣고 검토에 보낸다. 제출용 서비스 계정은 Firebase 것
  (`firebase-adminsdk-fbsvc@doit2-1b006.iam.gserviceaccount.com`)을 Play Console 사용자로 초대해서 쓴다.
- 업데이트 강제: 2026-11-18에 Play 스토어에 0.3.0이 보여서 안드로이드 `min_version`을 `0.3.0`으로 올렸다.
  아이폰도 같은 날 App Store Connect에서 출시를 확인하고 `0.3.0`으로 올렸다.
- 무료 EAS 제출 대기열은 저녁에 수십 분 걸릴 수 있다. 급하면 AAB를 받아 Play Console에 직접 올린다.
- App Store Connect의 첫 버전 이름은 "1.0"이지만 안의 빌드는 0.2.0이었다. Apple은 빌드 버전으로 비교해서 0.3.0을 받아 줬다.
- 윈도우에서 Windows PowerShell은 `npx`가 실행 정책에 막힌다. 터미널에서는 `npx.cmd`로 부른다.
- 클라우드 시뮬레이터(Expo Simulators): `eas.json`의 `simulator` 프로필로 빌드하고
  `eas simulator:start --platform ios --device "iPhone 17 Pro Max" --build-id <id>`로 연다.
  이 계정은 세션이 **최대 40분**이다. 캡처는 `--pixel-density 3`로 찍으면 1320x2868이라 `app-store/raw/`와 크기가 같다.
  지도 공유를 딥 링크로 흉내 내면 줄바꿈이 사라져서 장소가 채워지지 않는다.
